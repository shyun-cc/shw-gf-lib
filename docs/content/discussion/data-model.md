> 设计讨论稿，业务实体尚未确认、尚未实现。以下是讨论记录模型，不是业务表结构。

## 讨论记录概念（建议）

| 概念 | 含义 | 关联 |
| --- | --- | --- |
| 场景 | 使用者、问题、输入与期望结果 | 对应若干需求 |
| 需求 | 可验证的预期行为与范围 | 来源于场景，关联验收项 |
| 决策 | 候选方案、依据、状态与影响 | 解释需求或边界的取舍 |
| 验收项 | 前置条件、操作、预期结果 | 验证需求 |
| 待确认问题 | 尚缺的证据或选择 | 阻塞相关需求或决策 |

上述内容可先以 Markdown 维护，无需为讨论记录建立数据库。

## 业务模型待确认

确认首个场景后，再识别业务对象、字段含义、标识、关系、生命周期和不变量；同时确认是否持久化、数据来源、保留期限与敏感性。当前不定义业务实体名、数据库类型、表、索引或迁移。
