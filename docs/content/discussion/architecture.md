> 设计讨论稿，业务架构尚未决定、尚未实现。

## 当前可核验边界

`docs/content/` 保存公开 Markdown，`docs/hugo.yaml` 与独立的 `docs/go.mod` 配置 OINK 站点；Hugo 将其构建为静态产物。仓库根目录的 Pages 工作流负责构建与后续发布。文档模块不决定未来业务技术栈。

## 待讨论的业务边界

| 边界 | 需要回答的问题 | 当前结论 |
| --- | --- | --- |
| 使用方式 | 库、服务、工具，还是其他交付形态？ | 待确认 |
| 调用方责任 | 哪些校验、配置、生命周期由调用方承担？ | 待确认 |
| 项目责任 | 哪些规则必须由本项目保证？ | 待确认 |
| 数据持有 | 是否保存状态，谁拥有数据？ | 待确认 |
| 外部依赖 | 是否需要网络、存储或其他服务？ | 待确认 |
| 兼容边界 | 版本、错误与变更如何影响使用者？ | 待确认 |

在场景明确前，不选定框架、模块划分、部署拓扑或基础设施。
